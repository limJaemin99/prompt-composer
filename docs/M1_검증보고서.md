# M1 검증 보고서 — file:// 파이프라인 실동작

- 검증일: 2026-07-08
- 대상: `dist/index.html` (커밋 기준 빌드, 144.3KB 단일 파일)
- 방법: 설치된 실제 브라우저(Chrome·Edge)를 puppeteer-core(프로젝트 외부, 일회성)로 구동해
  `file://` 프로토콜 그대로 자동 검증. 사람 확인이 필요한 항목은 하단에 별도 표기.

## 자동 검증 결과 (Chrome · Edge 동일)

| 검증 항목 | 결과 | 비고 |
|-----------|------|------|
| `file://` 로드 (페이지 타이틀 확인) | ✅ | `protocol: "file:"` |
| 보안 컨텍스트 | ✅ `isSecureContext: true` | Chrome·Edge는 file://을 신뢰 오리진으로 취급 |
| 클립보드 복사 | ✅ **clipboard-api 1차 경로로 성공** | 폴백(execCommand)까지 갈 필요 없었음. 폴백 경로도 코드에 존재 |
| 클립보드 실제 내용 일치 | ✅ | 복사 후 `readText()`로 샘플 텍스트 일치 확인 |
| .txt 다운로드 | ✅ | `검증샘플_YYYYMMDD_HHmm.txt` 패턴 준수 |
| UTF-8 BOM | ✅ | 파일 선두 바이트 `EF BB BF` 확인 |
| 한글 무손상 | ✅ | 다운로드 파일 본문이 원본과 일치 |
| 콘솔 에러 | ✅ 0건 | pageerror 0건 포함 |
| 외부 네트워크 요청 | ✅ 0건 | 유일한 요청은 `file://` 자기 자신 (오프라인 요건 충족) |

## 사람 확인이 필요한 항목 (자동화 한계)

자동 검증은 **headless 모드**로 수행되어, 아래는 실제 창 환경에서 한 번 확인이 필요하다:

1. **탐색기에서 `dist/index.html` 더블클릭** → 화면이 뜨는지
2. 화면의 **[프롬프트 복사]** 클릭 → 메모장에 **Ctrl+V** → 한글 그대로인지
3. **[.txt 다운로드]** 클릭 → 받은 파일을 **메모장 더블클릭** → 한글이 깨지지 않는지
